# 脚本目录说明（Codex 键鼠 / 读屏工具）

> 建立时间：2026-10-09
> 用途：把「读屏 + 点 + 输入」这套自建能力集中放好。以后直接把本目录发给 Codex，就能直接开工，无需再找路径。
> 配套文档：本目录上一层的 `1.` `2.` `3.` 三份 md。

## 文件清单

| 文件 | 作用 |
| --- | --- |
| `read-screen.ps1` | 读屏主工具。UIA 控件树（带坐标）/ OCR / auto，可指定窗口 |
| `capture.ps1` | 单纯截屏存 PNG（支持全区/指定窗口/指定区域/缩放） |
| `InputHelper.psm1` | 键鼠操控模块：`Click-Control`、`Type-Text`、`Send-Hotkey`、`Set-AppWindow` 等 |
| `win.ps1` | 补充工具：按窗口标题子串定位并把窗口**可靠**拉到前台，再可顺带敲一条命令 |

> 前三个是从 `D:\agent\ScreenReader\` 复制过来的原版；`win.ps1` 是 2026-10-09 实测后补的（见下）。

## 常用命令

```powershell
# 读屏（自动：先 UIA，文字太少转 OCR）
powershell -NoProfile -ExecutionPolicy Bypass -File ".\read-screen.ps1"

# 只要控件树（带坐标，适合"告诉我点哪"）
powershell -NoProfile -ExecutionPolicy Bypass -File ".\read-screen.ps1" -Mode uia

# 读指定窗口
powershell -NoProfile -ExecutionPolicy Bypass -File ".\read-screen.ps1" -Mode uia -Window msedge

# 载入键鼠模块
Import-Module .\InputHelper.psm1 -DisableNameChecking
Get-CurrentContext
Click-Control -Name "登录" -Window msedge -DryRun
Type-Text "whoami"
Send-Hotkey "{ENTER}"

# 按标题把窗口拉到前台（标题支持子串），并敲一条命令
powershell -NoProfile -ExecutionPolicy Bypass -File ".\win.ps1" -Title "CodexVis-Console" -Text '"ok" | Set-Content D:\tmp\ok.txt'
```

## 已知坑与对策（2026-10-09 实测补充）

1. **编码**：`.ps1`/`.psm1` 含中文时必须是 **UTF-8 with BOM**，否则 PowerShell 5.1 按 GBK 解析会语法报错。本目录四个文件都已带 BOM。
2. **`Set-AppWindow` 抢前台不稳**：本机实测会出现「前台不是目标窗口」，原因是 Windows Terminal 多标签 + Codex 自己抢焦点 + 管理员窗口。`win.ps1` 用的是更硬的办法（`AttachThreadInput` + ALT 解锁 + `BringWindowToTop` + `SetForegroundWindow`），实测更可靠。
3. **别误伤别人的窗口**：Windows Terminal 一个窗口多个标签，选错标签就会敲到别的会话里；发键前务必先用 `win.ps1` 确认 `FORE_TITLE` 是自己的窗口。
4. **控制台"选择"暂停**：窗口标题出现「选择 xxx」前缀说明处于快速编辑/暂停状态，先按一次 `Esc` 再输入。
5. **焦点会被 Codex 抢回**：Codex 发消息时会把前台抢回自己，所以「激活窗口」和「发键」要在**同一个脚本/同一次调用**里连续做完，中间不要插别的操作。
6. **OCR 不可信值**：IP / 路径 / 哈希 / flag 这类精确值不要用 OCR 结果，用 UIA 或让目标程序自己导出文本。
